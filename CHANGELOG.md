# Changelog

All notable changes to this project are documented in this file.
Versions follow [Semantic Versioning](https://semver.org/).

### Changed
- README, changelog and installation notes rewritten.

## [1.3.2] - 2026-11-18

Changes from the second independent code review.

### Security
- `usp_ChangeOwnPassword` accepted any user name and did not count failed attempts, which allowed
  unlimited guessing of another user's password. It now verifies the current password through
  `usp_TryLogin`, which applies lockout, and writes the audit entry itself.
- `usp_TryLogin` reads the user row with `UPDLOCK, HOLDLOCK`, so concurrent failures are counted
  correctly, and returns the same result for an unknown user as for a wrong password.
- A payment can be marked cancelled only when its credit note exists (trigger).
- `AuditLog.DbLogin` records the database login that wrote each entry.

### Fixed
- The session stored the user name as typed. A manager signed in as `Admin` could deactivate the
  account `admin`. The stored name is now used, and the self-deactivation check compares user ids.
- Changing a case type's minimum fee changed the totals of existing cases. Cases now store their
  fees (`Cases.MinimumFee`, `Cases.CourtFee`) when opened or when their case type changes.
- A customer stored without the leading zero of the ID number was not detected as a duplicate.
- Credit notes are saved before the original payment is flagged, in one transaction.

### Added
- `database/upgrade-from-v1.3.sql`, generated by `tools/gen_upgrade.py`, upgrades a v1.3 database
  in a single transaction without data loss. It can be run more than once.
- Eight integration tests, including a save without an ambient transaction.

### Changed
- `CaseForm` split into partial classes by concern (`Money`, `Saving`, `Timeline`).
- CI: `sqlcmd` runs with `-I`; each permission check must fail with the expected error; a v1.3
  database is upgraded on every build; missing LocalDB fails the build; the release archive is built
  in a separate job after all checks pass.
- The lockout unit test reads its limits from `create-database.sql`.

## [1.3.1] - 2026-11

Changes from the first independent code review, and display fixes.

### Security
- `security.sql` allowed workers to read password hashes and update `Users`. Workers now have no
  access to `Users`; sign-in and password change go through stored procedures that run as owner.
- A trigger rejects changes to the amount, date or method of a recorded payment.
- Only a manager can reopen a completed step (application check and trigger).
- Sign-in returns the same result, after the same work, for an unknown user and a wrong password.
  A deactivated account is reported only after the correct password is entered.

### Fixed
- Retrying a failed save of a new case created every timeline step twice. Case saving moved to
  `CaseService.SaveCase` and runs in a transaction.
- After a failed save, pending changes remained in the context and were written by the next save.
  `ChangeDiscarder` now discards them.
- The "case opened" audit entry did not include the case number.
- Israeli ID numbers with and without the leading zero were treated as different customers.
- Text on the dark list screens was light on a light background.
- Monetary totals and several receipt fields were truncated by narrow labels.

### Changed
- Case rules are validated in `CaseService` as well as in the form. Catalogue changes require the
  manager role in the business layer and are written to the audit log.
- Amounts are limited to 1,000,000,000 and step dates to 20 years ahead.
- The case type fee is applied as a minimum fee.
- Foreign keys for opposing parties and credit notes; `CHECK` constraints on amounts, percentages,
  roles and VAT; a payment can be cancelled once.
- Generic control and handler names (`button1`, `dataGridView1`, `btnOK_Click_1`) renamed.
- Money columns use `#,##0.00` and date columns `dd/MM/yyyy` in all lists.

## [1.3.0] - 2026

### Changed
- Tables, columns, classes, forms and variables renamed from transliterated Hebrew
  (`Tikim_Letipul_Orech_Din`, `frmAddCostemer`) to English (`Cases`, `CustomerForm`). The user
  interface remains in Hebrew. The EF model is generated from a single specification.
- Removed unused columns that held sensitive data (CVV, card expiry, ID copy, payer ID).

### Added
- Fixed court dates: steps dated by the court are not moved by recalculation.
- Jewish holidays on which the courts are closed are excluded from due dates; additional
  non-working days are configured in the office settings screen.
- Office settings (VAT rate, office details) stored in the database.
- Refunds of overpayments; the advance cannot exceed the case total.
- The current date is read from the database server, with a warning when the local clock differs.
- Optimistic concurrency for customers; open windows detect changes made by other users.
- Lockout after five failed sign-ins and deactivation of users.
- `database/security.sql` with database roles and an append-only audit log.
- `database/backup-nightly.cmd` and a backup reminder on the home screen.

### Fixed
- Completing or undoing an earlier step recalculated dates set by the court.
- Saving a case deleted by another user produced an unclear error.

## [1.2.0] - 2026

Changes from a usability review and a code review.

### Added
- Home screen listing overdue and upcoming steps; setup guide for new installations.
- Completion on the actual date, court-set dates with notes, undo of the last completion by a manager.
- Free-text search and filters on the cases list; case windows are no longer modal.
- Optional identification for opposing parties (ID, company number, passport) and international
  phone numbers.
- Payment kinds (fee, court fee and expenses); cancellation by credit note.
- Audit log viewer and database backup.
- Case deletion by a manager while no payment or completed step exists.

### Fixed
- `"12,5"` was parsed as 125 and `0.004` was saved as zero. Amounts are parsed strictly.
- The balance was copied from the last payment and ignored changes to the claim amount. It is now
  computed from the case total and all payments.
- Steps were ordered by date, so a court-set date could reorder the timeline.
- Changing a step duration in the catalogue moved deadlines of existing cases.
- Concurrent edits of a case overwrote each other. Cases have a `rowversion` column.

## [1.1.0] - 2026

Review and refactoring of the original project. The original code is the first commit.

### Fixed
- `getCustomerNegdi()` and `getOrechDinNegdi()` called themselves recursively, so opening an
  existing case caused a `StackOverflowException`.
- The sign-in button had no handler and the code read the wrong text boxes; the application
  skipped sign-in.
- Adding a customer always failed because required columns had no input fields.
- Case edits were never saved (`"UpDate"` compared with `"Update"`), and the timeline was not created.
- Completing a step threw at runtime (`Convert.ToInt32` inside a LINQ to Entities query).
- Payments indexed the wrong list (`IndexOutOfRangeException`) and could exceed the balance.
- The receipt screen had no implementation.
- Search filters were applied to already filtered results.
- Validation errors were displayed but did not prevent saving.

### Security
- Passwords stored as salted PBKDF2-SHA256 hashes; plain-text passwords are upgraded on sign-in.
- Changing a password requires the current password.
- Only the last four digits of a card are stored.
- The database file containing real data was removed and replaced by a script with fictional data.

### Added
- Business layer: `CaseScheduler`, `FeeCalculator`, `Validation`, `PasswordHasher`, `CaseService`,
  `AuthService`.
- User management, payments and receipts screens.
- Highlighting of overdue and upcoming cases.
- `database/create-database.sql`, unit tests, integration tests and a GitHub Actions pipeline.

### Removed
- Six unfinished or duplicate forms, three unused typed DataSets and unused resources.
